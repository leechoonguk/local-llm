# sandbox 하네스를 고칠 때 (이 워크스페이스의 절차)

`sandbox/.omp/` 는 피험자가 쓰는 하네스다. 우리가 그것을 고칠 때 지키는 다섯 가지 — `make check-sandbox-harness-edit` 가 넷을 기계로 확인한다.

## 1. 셀이 도는 중에는 고치지 않는다

벤치 셀이 실행 중일 때 하네스를 바꾸면 그 셀은 **두 하네스의 혼합**이 되어 무효다. 발진 전 `make preflight` 가
`pgrep -f "omp -p"` 로 셀 부재를 보고, 이 검사는 반대 방향 — **셀이 도는데 `sandbox/.omp` 가 더럽지 않은지** — 을 본다.

## 2. 고쳤으면 발진 전에 커밋한다

미커밋 상태로 셀을 띄우면 셀 경계의 원복(`git checkout -- sandbox`)이 수정을 지운다. 러너의
`--dry-run` 도 같은 원복을 수행한다 — **문법 확인 용도로 부르면 작업이 사라진다**(2026-08-29 에 두 번 겪었다).
러너 문법은 사본으로 본다: `cp .claude/skills/llm-bench/runner.ts /tmp/x.mts && node --check /tmp/x.mts`.

## 3. `git add -A` 로 sandbox 를 담지 않는다

피험자 산출물이 함께 커밋된다. 실제로 계측 커밋 하나가 진행 중이던 notice 도메인 전체(모델·스키마·리포지토리·
서비스·라우터·마이그레이션·배선)를 레포에 넣었고, 이후 셀들이 "과제가 절반 끝난 트리"에서 시작해 두 셀이
무효가 됐다. 하네스 커밋은 **경로를 좁혀** 담는다: `git add sandbox/.omp sandbox/decks`.
검사는 히스토리에서 **하네스와 피험자 트리가 같은 커밋에 섞인 적이 있는지**를 본다.

## 4. 신호·가드를 고치면 프루프를 같이 고친다

경계가 계약이다. 프루프 없이 바뀐 동작은 다음 사람이 되돌릴 수 있다 — 그리고 프루프가 초록이라고 가드가
도는 것도 아니다(한 가드는 프루프 초록인 채 편집의 91%에서 무동작이었다). 형태별 커버리지는
`.claude/rules/harness-proofs.md` 가 정한다.

## 5. 삭제에는 근거를 남긴다

신호·가드를 걷어낼 때는 **무엇을 재서 값이 없다고 판단했는지**를 캠페인 기록(`bench/<date>.<s1|s2>.<subject>.md`)에
남기고 커밋 메시지가 그 숫자를 인용한다. 되살릴 사람이 판단을 다시 할 수 있어야 한다.
