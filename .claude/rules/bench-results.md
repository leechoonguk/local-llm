# bench/ 결과 기록 표준

`bench/` 는 **결과만** 보관한다. 수행 환경(러너·브리핑·레퍼런스)은 `.claude/skills/llm-bench/`, 피험자 트리는 `sandbox/`. 사람용 원문은 `bench/README.md` "표준" 절이고, 이 규칙은 그중 기계로 검사하는 부분이다 — `make check-bench-results`.

## 레이아웃
- 플랫. 하위 디렉터리를 만들지 않는다(`pre-write` 훅이 막는다).
- 파일 하나 = 캠페인 하나. 이름은 `<YYYY-MM-DD>.<s1|s2>.<subject>.md`(필수) + 같은 stem 의 `.json`(원본, 선택·가공 금지).
  - `subject`: 소문자·숫자·점·하이픈(`ollama-qwen3.6-coder`, `omlx`, `llm-bench-runner`). 점은 모델 버전 때문에 허용한다.
  - 러너 원본 하나가 여러 캠페인의 원본일 수 있다. 그 경우 `.json` 은 md 짝이 없어도 되지만, 어떤 캠페인 `.md` 의 **출처 절이 백틱으로 그 파일명을 인용**해야 한다.

## `.md` 고정 5절 — 순서·제목 고정
`# 제목` 다음에 `## 조건`, `## 과제`, `## 결과`, `## 판단`, `## 출처`. 제목 뒤에 괄호 주석은 허용(`## 판단 (잠정, n=1)`).
- **조건**: `n=1`, `n≥2` 처럼 n 을 반드시 적는다. 실측이 아닌 값은 "추정".
- **결과**: 표. 열 이름에 `모델`, `과제`, `thinking`, `소요`, `게이트` 가 들어가야 한다(부분 일치, 대소문자 무시). 피벗 표(모델×과제)는 쓰지 않는다 — 실행 1회 = 행 1개. 무효 실행은 지우지 않고 "무효"와 사유를 적는다.
  - s1 단발 캠페인은 모델이 하나이고 게이트가 실행 테스트다. 그래도 같은 열을 둔다(`모델` 열에 같은 값 반복, `게이트` 열에 PASS/FAIL).
- **판단**: n=1 이면 제목이나 본문에 "잠정". 캠페인 간 종합은 `bench/README.md` "종합".
- **출처**: 비어 있으면 안 된다. 원본 `.json`, 세션 ID, 하네스 커밋.

## README 인덱스
`bench/README.md` 는 `## 표준`, `## 인덱스`, `## 종합` 절을 가진다. 인덱스 표는 모든 캠페인 `.md` 를 링크하고, 링크 대상은 실재해야 한다.
