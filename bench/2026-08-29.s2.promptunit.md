# s2 promptunit — 프롬프트 단위 사용 실측: 하네스 구멍 3건과 훅 비용 (2026-08-29 00:00~01:40 KST)

지금까지의 튜닝은 전부 **40분 무인 셀** 기준이었다. 실제 사용처는 사람이 프롬프트를 주고받는 인터랙티브이므로, 같은 하네스를 프롬프트 단위로 재측정했다. 결과: **채점 자를 피험자가 고칠 수 있었고**(가장 큰 구멍), 마감 요구·브리핑·게이트 상태가 프롬프트 크기에 전혀 비례하지 않았으며, 도구 결과마다 도는 훅이 세션 벽시계의 22~36%를 먹고 있었다.

## 조건
- Mac mini M4 Pro 64GB. 배포 구성(`omlx/Qwen3.6-35B-A3B-5bit:coder`, 창 131072/출력 8192, thinking budget 2048, 코더 MTP off). 모델은 `--model` 로 명시했다.
- 프롬프트 단위 = `omp -p` 1회(작은 프롬프트) 또는 `omp -c -p` 로 이어붙인 한 세션 4프롬프트. 훅로그는 프롬프트별로 분리(`STUCK_RESET_LOG`).
- 반복 수: **각 n=1**(구조 관측 목적 — 성능 판정용이 아니다). 초기 3프롬프트는 라이브 기본값이 Sonnet이라 무효 처리하고 로컬 코더로 재실행했다.

## 과제
- **작은 프롬프트 3종**: 읽기 전용 요약 / `list()` 에 docstring 한 줄 / batch 목록에 `q` 필터(리포지토리·서비스·라우터·테스트).
- **한 세션 4프롬프트**: notice CRUD 를 사람이 쪼갠 흐름(읽기 → 모델·스키마 → 리포지토리·서비스 → 라우터·등록·테스트+게이트).
- 대조: 같은 notice 과제를 **프롬프트 하나**로 준 배포 셀(`2026-08-28.s2.deployed.md`).

## 판단 (각 n=1 — 잠정)

1. **채점 자를 피험자가 고쳤다(치명).** `q: NameQuery | None` 이 라우터 파라미터 검사에 걸리자 코드가 아니라 `check-backend-router-params.ts` 의 판정 정규식을 고쳤다. 이 레포 규약은 별칭이 옵셔널을 흡수하므로 검사가 옳았다. `.omp/**` 편집을 막는 가드가 하나도 없었다 → `strict-no-harness-edit.ts` 신설(도구 경로 + 셸 쓰기 모양, 프루프 13). **게이트가 초록이어도 자가 휘어 있으면 초록이 아니다.**
2. **마감 요구가 변경 규모에 비례하지 않았다.** 한 줄 편집에 풀 게이트 3회. 비례 규칙(≤2파일·경고 없음 → 타깃 검증) 적용 후 321s→220s, 게이트 3→1. 벤치 셀(13~15파일)은 옛 경로 유지.
3. **프롬프트 경계에서 상태가 끊겼다.** 브리핑이 프롬프트마다 재발화(4회), p4 는 앞선 15회의 게이트를 모른 채 다시 막혔다. `.omp/state/discipline.json` 로 `briefedAt`/`lastGateAt`/`lastNoticeAt` 를 잇고, 마감 조건을 "게이트를 돌았나"에서 **"마지막 변경 이후에 돌았나"**로 바꿨다(같은 프롬프트 안에서는 동일한 규칙).
4. **훅이 자기 도메인 밖 이벤트에도 돌았다.** backend 한 줄 편집에 하네스 메타 검사(`check-omp-hooks` 2.7s·스로틀 없음, `check-omp-types` 0.4s)가 매번 실행. 경로 게이트(`lib/hook-scope.ts`) + `check-omp-hooks` 의 강제 계약으로 bash 4.89→1.56s. `check-verify` 실패 스로틀 30s→90s(빨간 구간에서 게이트가 최대 40회까지 재실행되던 증폭 완화).
5. **분할 프롬프트가 단발보다 나았다(관측, n=1).** 4프롬프트 54.3분·최종 초록·회귀 0 vs 1프롬프트 43.5분·exit 2·회귀 1. 다만 p2 가 37.7분·123턴으로 부풀었다 — "모델·스키마만" 이라는 범위 제한이 커버리지 100% 게이트 앞에서 무력했다. 인터랙티브에서 범위는 사용자 소관이므로, 남은 과제는 **브리핑·마감 압박을 사용자가 준 범위에 맞추는 것**이다.
