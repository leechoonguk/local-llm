# s1 K2-Horizon-MoVA-36B-A4B 프로브 + oMLX 0.7.0.dev4 재기준선 (2026-09-24)

웹 조사(9/24)에서 우리 체급(≤40B, 64GB)에 새로 들어온 유일한 후보 K2-Horizon-MoVA-36B-A4B(MBZUAI IFM, 9/3 공개)를 oMLX 내장 벤치로 1단계 프로브했다. 같은 날 oMLX 를 0.6.4→0.7.0.dev4 로 올렸으므로 3.6(기본 코더)·3.8(기각 이력) 도 같은 스택에서 다시 재 기준선을 잡았고, 3.8 은 남은 지렛대였던 ANE 프리필을 자동 튜닝으로 확인했다.

## 조건
- Mac mini M4 Pro 64GB. **`iogpu.wired_limit_mb` 가 재부팅으로 0(미설정)** 이었고 `/etc/sysctl.conf` 도 없었다 — oMLX 프로세스 상한 37.7GB(safe 티어 56GB 대신 Metal 기본 캡 51.8GB 기준). 32k 셀은 이 상한 근처(K2 phys_footprint 33.5GB)에서 잰 값이라 **교란 가능**. sudo 는 사용자 몫이라 이번 캠페인에서는 복구하지 않았다.
- 서빙 oMLX **0.7.0.dev4**(prerelease, DMG `macos26-27`, 앱 소유 서버, `ensure-app-server.sh` 관문). 0.6.4 앱은 스크래치패드에 백업.
- 내장 속도 벤치(`POST /admin/api/bench/start`): 프롬프트 4096·32768, 생성 128, 코퍼스 `code_python`, 웜업 quick, 단발(각 셀 n=1). 프로파일·thinking 무관한 원시 처리량이다(thinking 은 "—"). 단일 상주는 엔진 풀이 셀마다 대상만 로드(로그 `Loaded model … total:` 확인).
- 모델: `K2-Horizon-MoVA-36B-A4B-oQ4e`(mlx-community, 21GB, **스토어 파일 2종 수정 후** — 아래 판단 4), `Qwen3.6-35B-A3B-5bit`(23GB), `Qwen3.8-27B-4bit`(15GB, MTP off). 샘플링은 벤치가 고정(temp 1.0).
- 3.8 ANE 튜닝: `POST /admin/api/bench/ane-tune/start` backend qwen, sequence_length 2048, repeats 2(설정 비영구).
- K2 스모크(채팅 3회, 웜): 프로파일 그대로(temp 1.0/top_p 0.95, `reasoning_effort: high`, 창 131072/출력 8192). 툴콜 1회, `thinking_budget: 256` 요청 1회.

## 과제
- 속도: 위 벤치 2셀/모델. 게이트 = "3.6 대비 처리량"(코더 교체의 필요조건, `bench-model` 해석 기준: 정답률·응답시간이 기존 코더 이상). 9/2 3.8 프로브에서 쓴 40 tok/s 기준선을 같이 적는다.
- K2 기능 스모크: 응답 content 비어 있지 않음, reasoning 이 content 와 분리, 툴콜이 `tool_calls`(유효 JSON) 로 파싱, `thinking_budget` 이 K2 마커에도 작동.
- 3.8 ANE 튜닝: GPU-only 대비 프리필 향상률.

## 판단 (잠정, 셀당 n=1)
1. **K2 는 기능적으로는 완전하다**(reasoning 분리·툴콜·budget 전부 통과) — 로스터의 Gemma·Devstral 처럼 "말을 못 하는" 부류가 아니다.
2. **그러나 처리량이 3.6 의 절반 이하**: 4k 에서 프리필 0.39×·생성 0.52×, 32k 에서 0.33×·0.27×. 3.6 이 이미 notice 45~90분 캡에 걸리는 하네스라, 이 속도로는 2단계(장기 세션)에 올릴 근거가 부족하다. 카드 자체 보고(Terminal-Bench 2.1 58.6 vs 3.6 44.9)가 사실이라도 턴당 2~4배 느리면 캡 안에 못 끝낸다.
3. **32k 생성 15.1 은 구조적이다(확정, 22)** — wired 한도 복구(상한 50.2GB) 후 재측정해도 15.1 로 동일. 4k 38.4 → 32k 15.1 은 MoVA 어텐션의 긴 컨텍스트 비용이고, 131k 창을 쓰는 에이전트 세션에선 더 나빠진다. **K2 기각, 2026-09-24 스토어·레포에서 삭제**(사용자 결정 — 미사용 모델 일괄 정리). 재검증 시 `omlx/fix-k2-horizon-checkpoint.py` 로 파일을 다시 고친다.
4. **mlx-community oQ4e 는 그대로 oMLX 에 안 올라간다**(0.7.0.dev4 기준). 두 가지를 스토어 파일에서 고쳤다: (a) 전문가 키 `mlp.switch_mlp.*` 405개 → 내장 모듈 이름 `mlp.experts.*`(리네임 + 인덱스 갱신), (b) `self_attn.v_router` 48개가 4~5bit 로 양자화돼 "routers require BF16" 으로 죽어 `mx.dequantize` 로 BF16 복원 + config 의 해당 경로 양자화 `false`. `trust_remote_code` 로 리포 동봉 모듈을 돌리는 우회는 외부 코드 실행이라 택하지 않았다. 재다운로드하면 `omlx/fix-k2-horizon-checkpoint.py` 를 다시 돌린다(멱등).
5. **3.8 은 재기각**: 앱 업그레이드로 디코드는 변하지 않았고(15.0 tok/s, MTP off), ANE 튜닝이 프리필을 +54.5% 올려도 디코드 상한이 그대로다. 외부 M4 Pro 64GB 실측(~21 tok/s, MTP on)과 같은 대역 — dense 27B 는 M4 Pro 대역폭(273GB/s)의 문제라 소프트웨어로 안 풀린다.
6. **K2 의 사고량은 크다**: high 에서 1문장 질문에 ~1600 tok(3.6 은 같은 부류 질문에 수백). budget 2048 이 자주 발화할 것이고, 2단계에 올린다면 high+budget 2048(3.6 과 같은 조건) 과 medium(네이티브, 사고 거의 0) 을 축으로 잡아야 한다. `make smoke` 로 K2 를 볼 때는 `max_tokens` 를 budget 보다 크게(≥4000) 줘야 오탐이 없다.
7. **"MTP+budget 공존 불가" 는 0.7.0.dev4 에서도 유효하다(외부 드래프터 경로)**: 소스가 budget 을 허용하도록 바뀌었지만 Qwen VLM 어댑터(mRoPE)는 positioned verify sampling 게이트에서 거절돼 BatchGenerator 로 폴백한다(14). DFlash 는 budget 을 조용히 무시하고 긴 생성에서 더 느려 기각(16·17). 남은 길은 **네이티브 Lightning MTP**(체크포인트 내장 MTP 헤드, `mtp_enabled`) — mlx-community 5bit 에는 헤드가 없어 400(15). 그래서 oMLX 개발자 변환 `Jundot/Qwen3.6-35B-A3B-oQ4e-mtp`(20GB, MTP 1층 보존)를 받아 다음 셀에서 잰다. 패치 `patches/mlx_lm_mtp/batch_generator.py` 는 `_apply_processors` 로 프로세서를 적용하고 문법 제약만 폴백시키므로 budget 공존 가능성이 있다(미실측).
8. **네이티브 Lightning MTP + budget 은 공존하지만 M4 Pro 에선 손해다**(19~21): 같은 oQ4e-mtp 로 MTP on 60.8/49.6 vs off 75.3/57.0 tok/s(−19%/−13%). 원인은 로그가 직접 말한다 — MTP 헤드 1층(d1)만 수락되고 d2·d3 는 0, 수락률 45~63%, 루프 세금 1.32(MTP 스텝이 표준 스텝의 1.3배) — 대역폭이 좁은 M4 Pro 에선 검증 오버헤드가 수락 이득을 넘는다(M4 Max·M5 Max 의 외부 실측이 우리에게 이식되지 않는 이유). 엔진 자체가 파킹으로 인정한다. **MTP 계열 전부 재기각**(vlm_mtp 게이트 거절·DFlash budget 무시·네이티브 MTP 순손실). oQ4e-mtp 는 MTP off 로는 5bit 와 동속(품질 미검증) — 코더 교체 근거 없음, 삭제 후보.
9. **oMLX 0.7.0.dev4 는 3.6 에 해롭지 않았다**: 4k 생성 73.9 tok/s 는 8/28 MTP-on 실측(75.8)과 같은 대역(이 벤치는 MTP/budget 무관). 131k 프리필 재검증은 하지 않았다(9/2 283.5 tok/s 기준선은 0.6.4).
