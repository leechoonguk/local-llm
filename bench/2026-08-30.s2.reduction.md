## 판단 (최종 실행 각 n=1 — 잠정)

- **하네스는 두 신호로 충분하다.** 남은 것은 REG-WATCH(배선 규약)와 마감 게이트(가짜 완료 방어)뿐이다. 둘 다 omp 가 알 수 없는 프로젝트 고유 계약이고, 나머지는 전부 걷어냈다(4,083 → 333줄).
- **컨텍스트 관리는 omp 소관이다.** 짝 비교에서 상한 ON 팔은 자체 종료 0/3·초록 0/3, OFF 팔은 1/3·1/3 이었고 회귀는 6셀 모두 0 — 컷이 필요하다는 근거가 없었다. 컷을 정당화하던 옛 수치(ctx 45k→22k)는 개입이 셀당 20~34건의 도구 호출을 취소하며 컨텍스트를 부풀리던 시절의 것이다.
- **컨텍스트 조작은 진행 중인 작업에만 안전하다.** 상한 0.25 프로브가 읽기 단계에서 잘리자 남은 문맥이 "베이스라인 초록"뿐이라 피험자가 과제를 시작도 않고 "All gates green"으로 종료했다(206s·writes 0). 이 레포가 TAIL-TRIM 으로 한 번 겪은 실패형과 같다.
- **integration 실패는 모델 판단이 아니라 두 결함이었다.** ① 모든 산출물 이름이 파생되는 오퍼레이션 코드가 setup 이 지우는 두 파일에만 있었다(11셀이 9가지 코드를 지어냈다) ② 채점이 `git status` 줄 수라 아무것도 안 하면 6/6, 정확히 복원하면 0/6 이었다(writes 0 인 6/6 행이 기록에 3개 있었다). 둘을 고친 뒤 integration 은 **3/3 완주**했다.
- **베이크한 설정이 실행 경로에서 먹는다**(9·10행). 오버레이·`--model` 오버라이드·주입 없이 라이브 설정만으로 돌렸고, 서버 로그의 모델 분포는 코더 93 + aux 2 요청으로 역할 해석이 정확했다. rest 는 1660s→1665s·15/15 로 재현됐고, integration 은 6/6→3/6 으로 재현되지 않았다 — 설정 문제가 아니라 이 과제의 실행 편차로 본다(n 을 더 쌓아야 한다).
- **캡 30분과 40분은 다른 실험이다.** 30분에서 rest 는 미완성 1이 기본값이었고, 40분에서 처음 초록이 됐다. 캡을 섞어 비교하지 않는다.
