# s2 러너 검증 / 상한 — Sonnet, sandbox (2026-08-24)

로컬 모델 캠페인이 아니라 **러너 파이프라인 end-to-end 검증**이자 강한 클라우드 모델의 **상한(ceiling)** 참고다. `.claude/skills/llm-bench/runner.ts` 를 실제 셀로 처음 돌려, **두 과제(Mode A integration / Mode B rest)** 모두 세팅→omp 피험자→게이트 채점→원복이 동작하는지 확인했다.

## 조건
- M4 Pro 64GB. 피험자 트리 `sandbox/`(batch·user·integration 코어, 포트 분리), **git 없이** baseline `make verify` exit 0.
- 모델 `anthropic/claude-sonnet-4-6`(클라우드, omp 등록 최신 Sonnet). thinking 기본, `--model` 외 플래그 없음. n=1, 셀 상한 1800s.
- 러너가 baseline 확인 → `omp -p` 독립 프로세스 → 채점 → `git checkout -- sandbox && git clean` 원복. 로컬 서빙(oMLX/Ollama) 무관.

## 과제 (둘 다)
- **integration**(Mode A): 외부 API I2570 을 형제 `search-food-raw-material` 을 본떠 추가. 기대 6. 러너가 부모 상태(바코드 정답 제거)로 만들고 채점.

## 판단 (n=1, 잠정)
- **러너 파이프라인이 두 과제 모두에서 실증됐다.** dry-run 이 못 보던 부분(실제 피험자 실행·산출·채점·원복)이 integration·rest 두 셀 다 통과했다. Mode A 의 부모 상태 복원(정답 은닉)·`reference_names_reused` 감사, Mode B 의 HEAD 진행이 모두 정상. 이후 로컬 모델(oMLX 3.6/3.8 등) 셀도 같은 러너로 돌린다.
- **Sonnet 상한**: integration(7/6, 7m36s) · rest(15/13, 10m10s) 모두 회귀 0·미완성 0·게이트 초록으로 완주. 로컬 모델과 티어가 달라 직접 비교 대상은 아니고, "게이트를 통과하는 완성본은 이 정도 규모" 라는 위쪽 기준점이다.
- 산출물 15/13 은 기대(13)를 넘지만 게이트 통과 + 회귀 0 이라 과잉이 아닌 정상 완성으로 읽는다(형제 `batch` 대비 테스트 세분화 등).
