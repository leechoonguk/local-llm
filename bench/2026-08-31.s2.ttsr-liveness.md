# s2 ttsr-liveness — TTSR liveness 계약의 실측 검증 (2026-08-31)

liveness 표본 계약(`check-omp-rules` `checkTriggerLiveness`, 커밋 55e2aad)을 omp **실엔진**(`omp ttsr test` — 공식 검사 도구)과 라이브 세션으로 검증했다. 계기: 스태시된 하네스 수정이 `tool:write(backend/alembic/versions/*.py)` 스트림을 추가하면서 condition 을 명령 모양으로 좁혀 그 스트림이 죽었는데, 기존 frontmatter 검사가 전부 통과했다.

## 조건
- omp ttsr test(매칭 엔진 단위) + `omp -p` 라이브 세션(주입 단위, 코더 `omlx/Qwen3.6-35B-A3B-5bit`) — n=1/케이스.

## 과제
- 하네스 검증(코딩 과제 아님): liveness 계약이 omp 실엔진·라이브 주입과 일치하는지. 표본 발화 6, 죽은 스트림 1, 음성 대조 2, 직렬화 1, scope 형식 1, e2e 1.

## 판단 (각 n=1 — 잠정)
- liveness 계약은 실엔진과 일치한다: 표본이 발화하는 규칙만 통과시키고, 죽은 스트림(2a)은 표본을 쓸 수 없어 저작 시점에 드러난다.
- 새 표준 2건 추가: 따옴표 든 condition 은 `\\?` 로 직렬화 내성(4), scope 는 문자열 한 줄로 표준화(5). 근거는 `omp-conventions.md` 에 실측과 함께.
- 검증 도구: 규칙을 고치면 `omp ttsr test --rule <파일> --source tool --tool <t> --path <p> '<표본>'` 이 공식 경로다 — 원형·직렬화형 둘 다 돌린다.
